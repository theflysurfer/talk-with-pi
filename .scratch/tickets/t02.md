## Parent

#1 (spec Pont vocal Pi)

## What to build

Recevoir un `user_text` sur le WebSocket et l'injecter dans la session Pi vivante via `pi.sendUserMessage`, en followUp par défaut (steer en commande vocale explicite à part), avec accusé de réception (state working). Le message apparaît dans pi-web comme un message normal, sans enveloppe, source distinguable (extension).

## Acceptance criteria

- [x] wscat envoie `user_text` → le message arrive dans la session Pi telle quelle (protocole testé au seam WS ; injection sendUserMessage câblée dans index.ts)
- [x] Pi occupé : le message part en followUp (file), ne coupe pas le run (`deliverAs: "followUp"`)
- [x] Accusé : state phase=working (ou error si l'injection échoue)
- [x] Le message apparaît dans pi-web sans doublon ni instruction ajoutée (sendUserMessage injecte en message utilisateur réel)
